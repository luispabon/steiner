# Context management internals

User guide: [Context management](../user/context-management.md).

Parent context is bounded by delegation (child transcripts stay out of the conversation), per-source byte budgets, and compaction into new conversation generations.

## Delegation

Child turns stay out of the parent transcript, and the parent receives a bounded result. See [Sub-agent delegation](sub-agent-delegation.md).

A `documentor` child selects `DelegatedDocumentorWorkflowMode`, so `sectionDocumentorChild` renders its duties and write-scope text into that child's memoized preamble. Prompt composition is in [Sub-agent delegation internals](sub-agent-delegation.md#canon-and-workflow); the write rules are in the [user guide](../user/sub-agent-delegation.md#documentor-type).

## Prompt assembly

The source order is fixed in `internal/prompt/source_plan.go`. Static sources come first so the prefix stays stable for cache reuse.

| Step | Source (`ContextSource`) | Budget | Notes |
|------|--------------------------|--------|-------|
| 1 | `preamble` | none | Memoized per session |
| 2 | `global_agents_md`, `project_agents_md` | none | Never truncated |
| 3 | `project_context` | 8000 bytes (`fallbackProjectContextBudgetBytes`) | Truncated when over |
| 4 | `skill` | 107520 bytes (`defaultSkillBudgetBytes`) | Exec and oneshot only |
| 5 | `phase_prompt` | none | Oneshot phases |
| 6 | `session_date` | none | See [Session date assembly](#session-date-assembly) |
| 7 | `conversation` | none | Pass-through |

- `applyBudget` (`internal/prompt/source_render.go`) marks over-budget project context and skill blocks as `Truncated`. `AssemblyPolicy.Budgets` overrides the defaults; negative values are rejected (`internal/prompt/budget.go`).
- `IsSystemZone` covers the preamble, phase prompt, and both AGENTS.md sources. Every other source renders as a user message (`blockMessage`). `renderBlocks` merges consecutive blocks of the same role.
- `conversation_summary` is not produced as a context block by the current source plan. Compaction stores a `summary`-role conversation message; `toProviderMessage` (`internal/agent/message_convert.go`) projects it to a user message wrapped in `summaryContextPrefix` and `summaryContextSuffix`. The summary therefore reaches the model as user-role historical context without passing through `blockMessage`.
- Interactive sessions pass no skill names to static assembly. The enabled set is held by `interactive.Skills` (seeded from `Dependencies.SkillNames`) and reaches the model through the envelopes below.
- An assistant message marked `Message.Incomplete` is projected to the provider with a trailing interruption note (`toProviderMessage` in `internal/agent/message_convert.go`), so the model learns its previous streamed response was cut off. The stored message and the emitted event keep the exact streamed text.

### Preamble and static cache

- `CachedSystemPreamble` (`internal/agent/context_manager_base.go`) rebuilds the preamble only when an input changes: override, delegation enabled, async sub-agents, orchestration level, advisor, LSP, workflow mode, system suffix, sandbox enabled, or sandbox writable mounts.
- File-backed sources live in `prompt.StaticContextCache` (`AssemblyOptions.CachedStaticContext`). Each partition reloads only when its key changes: AGENTS.md paths; project root, budget, extra and ignore files; skill roots and enabled skill names. The skill key excludes `SkillsBundledFS`, so a cache must always pair with one bundled FS.
- A change to `AssemblyOptions.StaticContextScope` drops every partition (`beginScope`, `internal/prompt/assembler.go`).
- Caches are created per interactive session, per oneshot phase, per exec run, and per delegated child.

### Interactive skill delivery

Interactive sessions keep skills out of the static prefix, so toggling a skill never changes the cacheable part of a request. `internal/interactive/skill_injection.go` puts envelopes ahead of the user's text in the next submitted message:

```
<steiner-skill name="..." state="active|inactive" bytes="N">
...
</steiner-skill>
```

- `bytes` is the body length, so envelopes are length-delimited.
- On submit, `skillDeltaBlocks` diffs the enabled set against `EffectiveSkills`. Deactivations come first, then activations for newly enabled skills. Existing messages are never rewritten.
- `EffectiveSkills` folds envelopes across user messages in order. An activation replaces that skill's block and moves it to the end. A deactivation removes it.
- `SplitSkillBlocks` (`internal/prompt/skill_blocks.go`) reads an optional leading mode notice and then envelopes. It stops at the first malformed envelope and keeps the rest of the text as is.
- A body over `prompt.SkillContentCapBytes` is cut on a UTF-8 rune boundary and ends with `[truncated: skill exceeded the 107520-byte cap]`. The cap applies to the skill body; the `## Active Skill:` heading, the framing text, and the envelope tags are added outside it. Loading such a skill emits `skill_truncated` with the original size and the cap.
- On resume, replayed envelopes emit `skill_state` events (`internal/interactive/replay.go`).

## Request event snapshots

`output.NewAPIRequestEvent` (`internal/output/event_model_call.go`) builds the per-request event behind the context report, and `interactive.snapshotSink` (`internal/interactive/wiring.go`) stores it for later reporting.

- `MessageHashes` are the first four bytes of `sha256` over `provider.AppendMessageHashInput`. One buffer is reused across a request, so the hash input is never materialized as a string, and cache diagnostics hashes messages through the same append path.
- `PromptBytes` is the sum of each message's role and content length. `BlocksBytes` is the sum of `ContextBlock.ByteSize`.
- `ToolsBytes` is the encoded length of the tool definitions, computed by `json.Marshal` on every request. Tools are re-cloned into each request, so the encoding is not memoized by slice identity: an in-place edit of a reused slice would otherwise report a stale size.
- Messages, tools, blocks, and the `MaxTokens` value are deep-copied into the event, so later mutation of the conversation cannot reach it. `snapshotSink` then stores its own deep copy through `SnapshotStore.Store`, because every later sink receives the same payload and nothing guarantees it stays unmodified.
- `ParentSnapshot` and `AgentSnapshot` clone before returning, so a reader cannot mutate stored state.
- `SnapshotStore` (`internal/interactive/snapshot_store.go`) keeps a parent snapshot that child requests never replace and one retained snapshot per sub-agent keyed by agent ID. At most `snapshotAgentLimit` (32) agents are retained, evicted in last-write order, and `Clear` drops both. Retained snapshots are dropped when the conversation is cleared or a saved session is loaded.
- `RequestContextReport` (`internal/interactive/actions.go`) carries the `AgentID` its report describes. An empty ID reports the parent snapshot, a non-empty one that sub-agent's retained snapshot; `emitContextReport` (`internal/interactive/reports.go`) marks every emission with `output.WithContextReportAgent`, and a missing snapshot still emits a report body that says so.
- The TUI caches agent-marked reports per agent for the context report overlay's sidebar and replaces the detail pane only when that agent is selected (`internal/tui/context_overlay_agents.go`). Agent-marked reports arriving without the sidebar are dropped rather than replacing a single-pane overlay.

## Session date assembly

- `prompt.NewSessionDate` (`internal/prompt/session_date.go`) captures the date, zone abbreviation, and numeric offset that make up the line; `Parts` and `NewSessionDateFromParts` round-trip them. Sub-agents receive the parent's value through the `SessionDate` field of the delegation dependencies (`internal/delegation/registry.go`).
- `interactive.Session` stores the parts as `session_date` on the session record (`StartDate`, `internal/session/session.go`). `saveSession` writes them, and `loadSession` restores them, so a resume renders the identical line including the zone abbreviation on a later day or in another zone. A record without the field captures the current date once on load and saves it immediately. `session.Fork` copies the field, and `applyRotationLocked` (rotation and `/clear`) captures a new date. Compaction and delegated runs read the session's value through `SessionDate()`, so the line does not change.
- The date block sits after the static sources and before the conversation, and is never budgeted. It is user role, so it stays out of the system-zone prefix. It merges into an adjacent user block, or starts one after a system-zone phase prompt.

## Token estimation

`EstimateChatRequestTokenEstimate` (`internal/provider`) returns a `TokenEstimate` with `Tokens`, `RawTokens`, `Strategy`, and `Confidence`.

- Model IDs in `ctokActiveModelIDs` (`internal/provider/token_estimator_claude.go`, exact match after whitespace trimming) use `claudeTextCounter`. It calls ctok `CountContent`, which omits the single-message framing that ctok `Count` adds. Steiner does not add that framing back. Strategy `ctok`, confidence `low`.
- The ctok counter loads once. A failed load is returned on every call. The counter never falls back to another tokenizer.
- Calibration: `prepareTurn` fits the normal request once per model call and `executeChatRequest` reuses its raw count through `ChatRequest.RawPromptTokenEstimate`. The request is re-estimated only when `stripImagesIfVisionDisabled` changes the request, on the inline vision retry, or for compaction requests. A direct call without a prefit estimates the request itself. `ObserveUsage` records a per-model ratio from provider usage, and the strategy becomes `provider_usage`. Once samples exist, `calibrationForModel` scales whichever base estimate is selected, including ctok estimates. `Tokens` is calibrated and `RawTokens` is not.
- Fit checks use `Tokens`. `RawEstimatedPromptTokens` keeps the raw value for events and diagnostics.

## Compaction

Compaction runs when the context is too large. Two limits apply:

- **Soft trigger**: `compaction_threshold_tokens` when set (it must be below the effective context window), otherwise 70% of the window. Native providers compare it with the estimated prompt (`shouldCompactPrompt`, `internal/prompt/token_budget.go`). Stateful providers compare it with reported usage (see below). Field rules are in the [configuration reference](../user/configuration.md).
- **Hard fit**: `ModelTokenBudget.FitRequest` computes the calibrated prompt plus the completion reserve plus `SafetyMarginTokens`, and the total must fit `ContextSize`. Compaction requests are checked with `FitCompactionRequest`, which uses its own reserve.

`explicitMaxTokensValue` takes the first positive limit in this order: `MaxTokens`, then the `max_tokens`, `max_completion_tokens`, or `max_output_tokens` keys in `ExtraParams`, then the same keys in `Params`. `lowerToExplicitMaxTokens` lowers the reserve to that value when it is smaller, or sets the reserve when it is unset. With no explicit value, `clampUnsetCompletionReserve` clamps the reserve to the space left after the prompt and safety margin. The clamp floor is `min(reserve, provider.DefaultMaxOutputTokens)`.

### Stages

| Stage | Retained | Used when |
|-------|----------|-----------|
| Normal | 3 most recent compaction units | First attempt |
| Emergency | 1 most recent compaction unit | Normal did not apply, or the result still needs compaction |

- A compaction unit starts at each user-role message, and at an assistant message when the current unit already holds one, so tool results stay with the assistant call that produced them (`splitCompactionTurns`, `internal/agent/compaction_candidate.go`). Retention is a strict tail: it never reaches further back for the latest user message.
- Older turns are assembled through normal prompt assembly, followed by a final user message that asks for a summary. The request carries the same tool definitions as a normal turn (`provider.CloneTools`).
- Normal mode uses `internal/prompt/templates/compaction_default_body.md.tmpl`, which asks for eight numbered sections: task and goal, repository state, work completed, key findings and decisions, problems, remaining work, verification, and user preferences. Emergency mode uses `compaction_emergency.md.tmpl` and asks for a shorter, lossier summary.
- `deriveSummaryMaxTokens` (`internal/provider/resolved_model.go`) caps summary output as a share of the context window, bounded by a minimum and maximum, and never above the model's max output.
- The summary becomes the `SummaryPrefix` of a new `ConversationGeneration`, followed by the retained turns. `ConversationLineage` keeps every generation. The latest one is active. The stored message keeps role `summary` and its exact text. `toProviderMessage` (`internal/agent/message_convert.go`) projects it as a user message wrapped by the fixed historical-context notice and `<summary>` tags, so the model never receives the summary as system authority. The projection is deterministic, so the prefix stays cacheable while the earlier user context, session date, preamble and tools are unchanged; changing any of them creates a different prefix.
- Manual `/compact` uses the runner's prompt assembly options, so skills, project context, and preamble match a normal turn. Its tools come from `snapshotTools` (`internal/interactive/compaction_helpers.go`), which reads the last recorded parent request. With no parent request recorded, `cliRunner.CompactWithLineage` (`cmd/steiner/runner_run.go`) rebuilds the parent registry through `activeParentRegistry`, the same builder a run uses, so MCP exposure, search backend, sandbox and delegation tools are derived the same way. `sessionRunner` (`cmd/steiner/interactive_session.go`) waits for MCP initialization before the runner rebuilds, so late MCP tool definitions are registered first; an attempt cancelled with its caller is retried by the next request, a queued request whose own context ends returns without waiting for the running attempt, and any other initialization error is reported to every later request. A rebuild reflects the live configuration rather than the saved record: tools a server failed to advertise, tools disabled since the save, or a changed command in the config can make the rebuilt set differ from the parent request recorded before the save, so the summary prefix is then not the parent's prefix.
- A main summary request carries the latest generation's backend state. For a stateful provider, an in-place summary retires the generation's live transcript. `summarizeCompactionStage` records that retirement in `CompactionOutcome.BackendStateCleared` independently of `Applied`, reading the response's `ClearBackendState`, the request-scoped signal from `provider.WithBackendStateRetirement`, and an error already marked by `provider.BackendStateRetired`. A failed or cancelled summary may deliver or lose its terminal chunk, so the signal and the marker report the retirement when the chunk is lost.
- `clearRetiredBackendState` drops only the latest generation's backend state, including when a stage applies nothing or fails. On those paths the empty or failed outcome's conversation and pending archive are not adopted, and generation IDs do not change. An error that follows a clear keeps its text and chain and is marked, so `provider.BackendStateRetired` reports it. `CompactWithLineage` reports the clear as its `cleared` result. Manual compaction (`manualCompaction`, `internal/interactive/compaction.go`) drops the state when that result is true or the error satisfies `provider.BackendStateRetired`.

### Summary retries

`summarizeCompactionCalls` (`internal/agent/compaction_retry.go`) runs the summary calls of one stage for `summarizeCompactionStage`. A main stage makes at most `maxSummaryAttempts` (3) calls: the first call and two tail-only retries. A fallback target makes one call per stage and never retries; its empty reply fails the stage so the operation reruns on main. Worst case for one operation with a fallback selected: up to 2 fallback calls (the normal stage, then the emergency stage after an applied normal stage), then a main rerun of up to 6 calls (3 normal, then 3 emergency), 8 in total. Without a fallback, an operation makes up to 6 main calls. An empty normal stage returns its error before the emergency stage runs.

- `emptySummaryReason` classifies a reply with no text after `strings.TrimSpace`. Order: finish reason `length` (`summaryFailLength`), then tool calls (`summaryFailToolCalls`), then `summaryFailNoText`. `length` fails at once, with no retry.
- Text with tool calls is accepted. `noteSummaryReply` emits one `compacting` note event. When a retry recovered, it names the attempt and lists each failed attempt through `CompactionSummaryAttempt.String`. When the reply carried tool calls, it says they were ignored.
- Call 1 is `compactionExecutionPlan.request` unchanged. `retryCompactionRequest` copies that base request and appends `prompt.RenderCompactionRetryInstruction` (`internal/prompt/templates/compaction_retry.md.tmpl`) to the final message only, so steering never stacks. The failed reply is never replayed. The last call (`prompt.CompactionRetry.Final`) also quotes up to `maxQuotedToolCalls` (3) attempted calls through `quoteAttemptedToolCalls`, each argument string cut to `maxQuotedArgChars` (120 runes, the ellipsis included, through `summarizeTextPreview`).
- Each retry is refitted with `FitCompactionRequest`. A request that does not fit fails the stage with `summaryFailRetryNoFit`.
- A retry keeps the tools, params, cache key and backend state. When an earlier call retired the main generation's backend state (`summaryCalls.cleared`), the retry drops `BackendState` and reseeds from messages. Usage and cache-reported tokens sum across every call of the stage.
- Exhaustion returns `compactionSummaryError` (`internal/agent/compaction_failure.go`): reason, attempts, the last reply's tool-call count, and `Details`, one entry per reply of the failed stage. It wraps no provider error, so the run loop does not retry the turn. `compactionFailedOutcome` leaves the state untouched, `clearRetiredBackendState` still drops retired backend state, and no deterministic or continue-uncompacted fallback exists.
- `output.CompactionSummaryAttempt` (`internal/output/context_diagnostics_types.go`) records each reply as the provider sent it: `attempt`, the raw `finish_reason` before classification, `completion_tokens` as reported (absent when the provider sent no usage), `tool_calls`, `reasoning_content` (whether `provider.Message.ReasoningContent` was non-empty), and `reason` (`length`, `tool_calls` or `no_text`; empty for a reply with text). `summaryAttemptRecord` builds it. Completion tokens never classify a reply, because some providers exclude reasoning tokens from them.
- `reportCompactionFailure` emits exactly one `ContextDiagnosticsEvent` with severity `skipped` and `compaction_result` `failed` (`output.CompactionResultFailed`), then marks the error so `CompactionFailureReported` stops manual compaction from emitting a second. Cancellation is not reported. An empty summary adds `summary_attempts`, `summary_failure_reason`, `summary_tool_calls` and `summary_attempt_details` (the `Details` list). The four summary fields and the list are `omitempty` on `output.ContextDiagnosticsEvent` and `output.ContextCompactionEvent`. The debug output renders each entry with `CompactionSummaryAttempt.String` as `summary_attempt attempt=N ...`.

Cache behaviour of the retries is in [prompt caching internals](prompt-caching.md#compaction-summary-retries).

### Compaction fallback

`RunRequest.CompactionFallback` names a second model for compaction summary calls. The zero value disables it. The CLI runner sets it per run request (`cliRunner.compactionFallback`, `cmd/steiner/runner_run.go`), and delegated children set it through `delegation.NewCompactionFallback` (`internal/delegation/compaction_fallback.go`, called from `internal/delegation/bootstrap.go`). Config fields are in the [configuration internals](configuration.md#compaction-fallback).

Selection (`compactWithFallback`, `internal/agent/compaction_fallback.go`):

- Selection runs once per compaction operation. The whole two-stage operation (normal, then emergency when needed) runs on the same target, and both stages share one summary request.
- Nothing is read or resolved when `CompactionFallback.After` is not positive or `Resolve` is nil.
- The clock is `RunRequest.Clock` when set, otherwise `time.Now`. `compactionCacheCold` treats the cache as cold when no main request is recorded (zero `LastMainRequest.At`), or when the idle time is greater than `After`. A warm cache runs on main.
- For a cold cache, `selectCompactionFallback` resolves the target. A resolve error, or a target with no provider, fails the attempt (see rerun below). A target with the same provider alias and backend model ID as main is not selected, and the operation runs on main.
- A selected target is announced once per compaction operation, after the fallback fit check passes in `summarizeCompactionStage` and just before its summary call. `compactionFallbackAnnouncement` (`internal/agent/compaction_fallback.go`) holds the announcement, and its shared flag keeps the normal and emergency stages from emitting twice. The announcement emits a compaction diagnostic at `compacting` severity on the compaction turn (`emitCompactionFallbackSelectedEvent`, `internal/agent/events.go`). It carries `CompactionModel` (`ProviderAlias/BackendModelID`), `CompactionModelAlias`, `FallbackStatus` `used`, the selection reason below, and the note `compacting on fallback model`. It emits no session health event, so the compacting state stays with the start and finish events. The finish event repeats them. The automatic run's skip event (`emitCompactionSkippedEvent`) names main's model and alias and repeats the status and reason when a fallback was discarded; the manual `/compact` skip event (`runManualCompaction`, `internal/interactive/compaction_helpers.go`) carries none of those fields. A target whose fit check fails emits no selected event.
- `CompactionModelAlias` is the configured alias of that model (`provider.ResolvedModel.Alias`). It is empty when the configured reference is a raw `provider/model-id` that repeats the canonical name, and when no alias was recorded.
- When the fallback applies a summary, the outcome records `CompactionModel`, `CompactionModelAlias`, `FallbackStatus` `used`, and `FallbackReason`. A selected fallback that applies nothing returns without those fields or a main rerun. The reason is `no recent request` when no main request is recorded. Otherwise it is `idle <m>m > <n>m` in whole minutes. When rounding makes the two minute values equal, it uses exact durations (`idle <duration> > <duration>`) so the reason still shows idle greater than the threshold.

Summary target and main (`summarizeCompactionStages.run`, `summarizeCompactionStage`):

- Retention split and fit checks on the retained tail and resulting state use the main request.
- `selectRetention` (`internal/agent/compaction_retention.go`) picks the tail: the largest of 3, 2, then 1 newest units that fits. The normal stage tries 3, 2 and 1 (`normalCompactionRetainTurns`); the emergency stage uses only 1 through `selectEmergencyRetention`. A candidate fits (`tailFitsWithBlock`) when the retained tail alone fits the main hard limit and the retained tail plus the latest request block (`fitWithRequestBlock`) plus the summary reserve (`compactionSummaryMaxTokensForMode`) plus `SafetyMarginTokens` is at most `ContextSize`. With an unknown window (`ContextSize` <= 0) every candidate fits. Selection is fit arithmetic only: it makes no model call, and each stage issues one summarizer call.
- When no normal candidate fits, `normalStage` returns a zero outcome without a model call and the emergency stage runs. The one-unit emergency tail is kept when it fits with its block. Otherwise it is kept without the block when the plain fit passes; the stage then runs with the block, and the budget ladder below may drop the block, so the outcome reports `RequestBlockDropped` rather than an error. When the tail does not fit even without the block, `selectEmergencyRetention` returns a `compactionBudgetMissError` wrapping `compactionTailTooLargeError`, and no emergency stage runs. `run` then retries the normal result without its block (step 4 of the ladder below) before failing.
- `compactionTailTooLargeError` (`internal/agent/compaction_escalation.go`) keeps the `compaction cannot solve this request:` prefix and reports `protected_outputs`, `retained_tail`, `request_block`, `summary_reserve`, `context_window`, `safety_margin` and `hard_limit`. Protected outputs are the tool-result and sub-agent-result messages in the newest unit after its last assistant message. Each part is a fit delta (`newCompactionTailTooLargeError`, `compactionTailTokens`), measured only when the error is built. `compactionOnMainAfterFallback` returns it without a main rerun, because main would select the same unit.
- When older units themselves do not fit the window, the emergency summary request cannot be sent and compaction fails with `emergency compaction could not reduce context enough`. A claude-like in-place summary sends the whole live record, so it can overflow when older units are very large.
- The summary output cap (`compactionSummaryMaxTokensForMode`) and the plan fit (`newCompactionExecutionPlanWithMode`, `FitCompactionRequest`) use the summary request's `ModelBudget`. On fallback that is the target's budget.
- A target plan that does not fit even after the block-stripped retry returns `errCompactionFallbackNotFit`. On main, the same failure is a not-applied outcome, and the emergency stage runs.

After the adopted state is in place, `emitCompactionDiagnostics` (`internal/agent/events.go`) reports the counts in `ContextCompactionEvent`. `SummarizedMessages` counts each adopted stage's source messages through `countSummarizedMessages`, excluding `MessageRoleSummary` and the replayed skill message; a two-stage result is the sum of both stages. `RetainedMessages` and `RetainedUnits` come from the retained slice, with units from `splitCompactionTurns`. `RetainedUserMessages` counts `IsRealUserMessage` matches and `RetainedSubAgentResults` counts the remaining user-role messages (`MessageSourceSubAgentResult`). The plain-text renderer (`internal/output/debug.go`) and the TUI banner report the same figures.

`ContextDiagnosticsEvent.Stages` and `ContextCompactionStage` (`internal/output/context_diagnostics_types.go`) hold one entry per applied stage, taken from `CompactionOutcome.StageSizes`: `stage` (`normal` or `emergency`), `retained_units`, `source_tokens` (the summary request prompt), `summary_tokens`, `retained_tokens` (the kept tail without protected outputs), `protected_tokens`, and `failed`. They are serialized in JSON output only; the plain-text renderer and TUI do not read them. `logCompactionStageSizes` also appends a `Stage Sizes:` line per applied stage to the compaction log. Only `compactConversationForBudgetWithSteering` calls `emitCompactionFailedDiagnostics`, and it emits only for an error that matches `compactionTailTooLargeError` (`errors.As`). It then emits a `compaction` diagnostic with severity `skipped` (so the TUI keeps its skipped banner) whose stages list the earlier applied stages for attribution, although their state was discarded, plus a failed `emergency` entry with `failed` set, one retained unit, and the measured `retained_tokens` and `protected_tokens`. Other compaction errors on that path emit no failed-stage diagnostic.

### Latest request block

Because normal compaction keeps only the last 3 units (`normalCompactionRetainTurns`) and emergency the last 1 (`emergencyCompactionRetainTurns`), the latest real user message is often summarized. Each stored summary therefore carries that request verbatim as a trailer: `body + "\n\n" + "[steiner:latest-request bytes=N]\n" + request`, where N is the request length in bytes. `withRequestBlock` first rewrites every `[steiner:latest-request` in the body to `[steiner latest-request`, so body text cannot forge a trailer. `SplitRequestBlock` parses the first `\n\n[steiner:latest-request bytes=` header: the count must be digits only and end the summary exactly, otherwise there is no block and the text is returned unchanged. Only `MessageRoleSummary` content is parsed, so a user message that types the header is never split. Body and request are returned as stored, untrimmed. Both functions live in `internal/agent/compaction_request_block.go`.

Selection runs in `summarizeCompactionStage` before the summary request, so it covers main, the fallback target, and both stages. `latestRequestBlock` scans the stage's source from the end for the newest `IsRealUserMessage` message with text to keep and reports status `new`. `IsRealUserMessage` requires role `user` and an empty `Source`: every synthetic user-role message is sourced, as `MessageSourceSubAgentResult`, `MessageSourceRuntimeNotice` (the turn-budget notice), or `MessageSourceSkillReplay` (the post-compaction skill replay). `requestMessageText` takes a recorded `Message.RequestText` first: `BuildDeliveryMessage` fills it with the user's text part beside the composed content, and `recordImageRewrite` fills it before image handling rewrites the content. It is stored with the session and is never projected to a provider or counted in token estimates. A message without it is skipped when it is marked `Message.VisionRouted`, a mark only real user messages get, since image handling has replaced the user's words with a routed description or placeholder. Any other message falls back to `legacyRequestText`, which parses the stored content with `prompt.SplitMessageBlocks` to remove the mode notice, skill blocks, pending line, and sub-agent result envelopes, then keeps only the text after the last sub-agent result close tag. Skill-only messages have no text and are skipped. `recordImageRewrite` (`internal/agent/vision_routing.go`) runs before every rewrite of a real user message: `routeImageToVision`, `stripImageFallback`, and the placeholder append in `freezeImagePlaceholders` or, for an image that was never frozen before delivery, `stripImagesFromMessages`. Frozen placeholder tokens are recorded in `MessageProviderMetadata.ImagePlaceholders`, so a second pass appends nothing and user text that happens to match a token is never mistaken for one. It records `legacyRequestText` of the content when the message has no `RequestText`, then sets `VisionRouted`; tool messages and sourced messages stay unmarked. An image-only turn therefore records no text and is skipped, while an image-plus-text turn keeps what it recorded. `agent.UserRequestText` exposes the same selection to the run preview (`lastUserPrompt`, `cmd/steiner/runner.go`), so a preview shows the user's words without the mode notice or delivery envelopes. When the trailing user message carries no such text, the preview is `sub-agent results (N)` for a results delivery (a sourced one, or a real delivery of results plus an image) and empty for an image-only turn. Two limits follow: a session from an older build can hold marked content with no recorded text, which yields no request for that image turn, and a placeholder that build stored carries no mark, so it can still be selected as legacy content. Without a request the block comes from the newest `MessageRoleSummary` in the source and is reported `carried`; otherwise it reports `none`. Images are never kept.

A new request is capped by `requestBlockCapBytes`: `min(16 KB, 5% of the context window in bytes)`, with `requestBlockMaxBytes` at 16 KB, `requestBlockWindowPercent` at 5, and `requestBlockBytesPerToken` at 4 bytes per token. An unknown window keeps 16 KB. `capRequestBlock` cuts the prefix on a UTF-8 boundary and appends `[truncated: N bytes omitted]`, which is extra to the cap. Both paths apply the cap, so a carried request shrinks when the window does, and a window whose effective cap rounds down to zero keeps no block at all.

The summary request replays the stage conversation exactly as a main request projects it, so a prior summary's block reaches the model inside its `<latest_user_request>` wrapper. That shared projection is the default: it keeps the cached prefix identical to main and keeps a `claude_subscription` in-place summary matching, because that path requires the replayed source prefix to equal its own transcript entries. `compactionStagePlan` (`internal/agent/compaction_stages.go`) builds the plan; when it does not fit and the source carries a block, it rebuilds the plan once from the block-stripped source (`stripRequestBlockSource`) and uses that plan when it fits. Stripping costs that call the shared prefix and the `claude_subscription` match. The outcome still stores a block, because `latestRequestBlock` selected it from the source before the plan was built. `stripRequestBlocks` removes the trailers only from the messages passed to `withHistoryNote`, so the history-archive note cannot re-quote a request. Both compaction templates state that Steiner keeps the latest summarized request verbatim after the summary and that the model should mention it briefly without quoting it.

`toProviderMessage` projects a stored summary as `summaryContextPrefix + body + summaryContextSuffix`, then, when a block exists, `requestContextPrefix + request + requestContextSuffix` in the same user-role message. `escapeCompactionTags` (`internal/agent/message_tags.go`) rewrites the angle brackets of every case-insensitive `<summary>`, `</summary>`, `<latest_user_request>` and `</latest_user_request>` in the body to `&lt;` and `&gt;`, and does the same for the request wrapper tags in the request. A tag matches from `<` through `>`: space-class characters, an optional `/`, more space-class characters, the name, then a tail. The space class (`compactionTagSpace`) is ASCII whitespace plus `\p{Z}`, `\p{Cf}` and U+0085, and it includes the newline. Without the slash, an opening tag's tail (`compactionTagTail`) is either only space-class characters, possibly none, or one run that starts with a character which cannot continue a tag name (`A-Za-z0-9_.:-`) and is neither a newline nor the closing bracket, then continues on the same line to the bracket, so an opening tag ends on its first line. With the slash, a closing tag's tail (`compactionTagEndTail`) takes the same two forms, but its run may cross newlines to the closing bracket, because an HTML tokenizer reads that run as the end tag's attributes; a closing tag may therefore span lines. A name continued by a name character, and a newline followed by more text, are not tags, so `<summary-table>`, `<summary.x>`, `<summary:x>`, `<summary_x>`, `<summaryish>` and `<summary` then a newline then text stay untouched. A stray slash, an `=`, a quote, an attribute, or prose takes the second tail form, so `</summary/ >`, `</summary"x">`, `</summary foo="x">`, `</summary` then a newline then text, and `</summary` then a newline then `>` are escaped. Prose such as `<summary is short and the request >` is escaped too; the words stay between the entities, so the model still reads them. The stored text is unchanged, and text without these tags projects byte for byte, so the prefix stays cacheable.

Retention can leave a block that no longer fits. `summarizeCompactionStages.run` (`internal/agent/compaction_stages.go`) walks a budget ladder:

1. A normal result that does not need emergency compaction (`needsEmergencyCompaction` false) is adopted with its block.
2. Otherwise the emergency stage runs and its result is adopted when it fits without emergency compaction.
3. Otherwise an applied emergency result is adopted without its block through `adoptWithoutRequestBlock`, which rewrites the stored summary text, issues no model call, and refits.
4. Otherwise the same retry runs on the normal result.
5. Otherwise the compaction fails with the original error.

Steps 3 and 4 apply only when the emergency attempt failed on budget alone: an applied result that still needs emergency compaction, a not-applied result that does not hard-fit, or an emergency tail too large even without its block, all marked by `compactionBudgetMissError`. A too-large tail runs no emergency stage, so only step 4 applies to it. Any other failure, such as a provider, fallback, or fit error, propagates unchanged, so the fallback rerun on main still happens. Step 4 reports `BackendStateCleared` when either attempt retired the backend state. Steps 3 and 4 report status `dropped` with `RequestBlockBytes` 0, as does `latestRequestBlock` when the effective cap rounds down to zero. Diagnostics report `RequestBlock` (`new`, `carried`, `dropped`, `none`) and `RequestBlockBytes` on `ContextCompactionEvent`, with a `request_block=<status>` note. `RequestBlockBytes` is the block's size and `SummaryBytes` the summary body alone, without the trailer. `StageCount` is 2 once the emergency summarizer call ran, and `Usage` then sums both stages through `sumUsageStats` (`internal/agent/compaction_stages.go`). The TUI summary row suffix is `latest request kept verbatim (new|carried)` or `latest request dropped to fit`, and the plain-text renderer (`internal/output/debug.go`) reports the same wording. The TUI compaction result and session history render the body, then `Latest request (verbatim):` and the request in a code fence built by `FenceVerbatim` (`internal/session/history_render.go`): one backtick longer than the longest backtick run in the request, never fewer than three, and no info string, so markdown in a request renders as typed. Session history strips history notes from the body; the TUI result shows the body as stored.

Rerun (`compactionOnMainAfterFallback`):

- A failed attempt (fit failure, provider error, resolve or build error, or empty fallback summary) is discarded. The whole operation reruns on main from the original `RunState`. The outcome then records `FallbackStatus` `skipped`, with `CompactionModel` and `CompactionModelAlias` naming the model used for the rerun, which is main. `FallbackReason` is `context too large for <ref>` only when the error is `errCompactionFallbackNotFit`. Any other error gives `fallback failed: <error>`.
- No rerun happens when `ctx.Err()` is set (parent cancellation or the turn timeout) or the error is `context.Canceled`. The error is returned as is.
- An error from the main rerun is returned.

Backend isolation (`compactionFallbackRequest`):

- The fallback request is a copy of the run request, used for summary calls only. It takes the target's provider, resolved model, budget, and compaction prompt override. Tools, conversations, and string lists are cloned. It clears `ParentTransportSession`, sets `CacheBaseline` to nil, and clears `CompactionFallback`. It is marked `compactionFallbackTarget`, and it is never passed to `Runner.Run`.
- Provider, executor, context manager, event sink, and `DrainInbox` are shared with the main run.
- `buildCompactionRequestWithMode` sets `BackendState` to nil for fallback targets, so a fallback summary does not send the main generation's backend state. The retirement signal, `ClearBackendState`, and `BackendStateCleared` apply only to main summaries: `compactWithFallback` discards a fallback outcome's clear, and `hideFallbackRetirement` hides a fallback error's marker when cancellation returns that error. `TransportSession` comes from `compactionFallbackIdentity` when the main session is set, and a fresh random key otherwise, so a stateful provider never treats a fallback summary as the main session.
- Fallback calls write `cold_start` false and leave the process-wide cold-start latch alone (`emitCacheDiagnostic`).
- Cache and transport identities for the fallback request are in [prompt caching internals](prompt-caching.md#compaction-fallback-identities).

`LastMainRequest` (type in `internal/agent/run_request.go`, recorded in `internal/agent/turn_progression.go`, carried by `internal/agent/conversation_driver.go`, seeded in `internal/agent/runner.go`):

- `turnProgressor.executeModelCall` sets `LastMainRequest` after each successful main model call, with `At` from the injected clock. Compaction calls, fallback calls, and failed calls do not set it.
- `ConversationDriver` carries the value across episodes. `finish` replaces it when an episode succeeds or its output is non-zero. Compaction and lineage advancement leave it unchanged. `LastMainRequest()` returns it.
- `seedLastMainRequest` keeps `RunRequest.SeedLastMainRequest` only when its provider alias, backend model ID, and `PromptCacheKey` all match the request. Otherwise the seed is zero. `Runner.Run` and `Runner.CompactWithLineage` apply it.
- Seeds come from the previous owner. Interactive `driverRun` (`internal/interactive/driver_run.go`) keeps its seed when a failed run returns zero. Manual `/compact` (`manualCompaction`, `internal/interactive/compaction.go`) passes the driver's `LastMainRequest()`. Delegated children keep `ChildSession.LastMainRequest` (`internal/delegation/session.go`) and pass it to continuation requests (`buildContinuationRequest`, `internal/delegation/follow_up.go`). A oneshot phase starts at zero (see [oneshot internals](oneshot.md#phase-driver)).
- `DriverSnapshot` carries the value and `DriverOptions.LastMainRequest` seeds it, so a host can resume a persisted one; a failed run keeps the seeded value (`agent.CarryLastMainRequest`). The interactive session stores the snapshot value in `session.Session.LastMainRequest` (`internal/session/session.go`) on both the live save and the retired-driver save, and a fork copies it. The record holds only the start time, provider alias, backend model ID and prompt cache key: no prompt, message or schema content.
- Loading a session restores the record (`restoreLastMainRequest`, `internal/interactive/last_request.go`) only when it has a start time, that time is not in the future, the model identity is complete, and the prompt cache key matches the loaded session's. `/clear` and session rotation drop it. A seeded value is still checked against the run's own identity by `seedLastMainRequest`, so a resumed request recorded for another model is ignored for that run; the stored record is not removed, and a later successful run replaces it.

Memoization (`CompactionFallbackTargets`, `internal/delegation/compaction_fallback.go`):

- Built providers are memoized by provider alias, backend model ID, and cache scope (`compactionTargetKey`). The cache scope is the main run's `PromptCacheKey`. For a delegated child, that is the child's cache key (`childCacheKey`, `internal/delegation/bootstrap.go`). Failed builds are not memoized. Targets are not closed.
- The session ID is not part of the key. The provider is built with the session ID of the first call for its key, and later calls with a different session ID reuse it.
- `Resolve` calls `ResolveModel` on every compaction that reaches it. Only the built target is memoized.

### Cache expiry indicator

The TUI reports a prompt cache idle deadline without waiting for a compaction to run. `RunRequest.PromptCacheTTL` (`internal/agent/run_request.go`) is set from `Config.PromptCacheTTL` when the run request is built, and the cache is presumed cold once it has elapsed since the last successful main request. Fallback selection keeps its own `CompactionFallback.After`; the indicator does not depend on a fallback target.

- `output.ModelCallFinishedEvent` (`internal/output/event_model_call.go`) carries `Success bool` and `CacheColdAt time.Time`. `turnProgressor.executeModelCall` (`internal/agent/turn_progression.go`) emits a successful main call with `Success` true and `CacheColdAt` set to the request start plus `RunRequest.PromptCacheTTL` when that value is positive. No fallback target is resolved or required. A zero TTL leaves `CacheColdAt` zero, and failed or cancelled calls report `Success` false with no deadline.
- `applyModelCallFinishedEvent` (`internal/tui/model_events_run.go`) stores the deadline only for a live successful call (`!m.devLog.replaying && !m.oneshotRunning && payload.Success`). Replay does not synthesise `ModelCallFinishedEvent`; a resumed, forked or loaded session starts without an indicator because `output.ConversationResetEvent` calls `applyConversationReset`.
- Every clear goes through `clearPromptCacheEstimate` (`internal/tui/prompt_cache.go`), which zeroes `promptCacheColdAt` and calls `syncPromptCacheAt`, so the footer and the sidebar drop the indicator at once. The clearing sites are `applyConversationReset` (`internal/tui/stranded_results.go`) for a loaded session, `resetConversationUI` (`internal/tui/model_update.go`) for `/clear`, `executeSwitchProfileAction` (`internal/tui/model_input_actions.go`) on a successful profile switch, and `commitModelSwitch` (`internal/tui/model_input_model_switch.go`) for an immediate model switch. A model switch that applies only after the in-flight turn keeps the current run on the old model: its estimate stays valid, and the next run's first successful main call replaces it. In-TUI oneshot phase calls are ignored while the run is active, and `OneshotFinishedEvent` handling (`internal/tui/model_events.go`) clears the estimate when the run finishes.
- `promptCacheStateAt` (`internal/tui/prompt_cache.go`) derives the state: the cache is cold only when `now.After(CacheColdAt)` is true, so the deadline instant itself still reports one minute left. It also returns the whole minutes left, which the sidebar holds as `cacheMinutes` alongside `cachePhase`.
- `cacheLine` (`internal/tui/sidebar_context.go`) renders the row and `contextSection` (`internal/tui/sidebar_sections.go`) appends it to the `context` card: whole minutes rounded up in dim text, `theme.WarnLine` at one minute or less, and `theme.Warn` for the `expired` value. The row is omitted when no deadline is stored. The status bar (`statusState`, `internal/tui/statusbar.go`) appends `cache expired` after the context segment once `promptCacheExpired` is set.
- There is no dedicated timer. `handleSessionTickMsg` (`internal/tui/model_update.go`) calls `syncPromptCacheAt(time.Now())`, which sets `status.promptCacheExpired` and the sidebar `cacheMinutes` and `cachePhase`, then calls `syncSidebar`. The cache fields are not set by `syncSidebar`. The tick runs once per second (`sessionTickInterval`).

### Compaction history archive

`agent.HistoryArchive` (`internal/agent/history_archive.go`) is optional on `RunRequest`. `summarizeCompactionStage` calls `withHistoryNote` after a summary is returned and before it builds the next state. `withHistoryNote` removes old lines beginning with `HistoryNoteMarker`, calls `Note`, and adds the current archive note to the summary. A `Note` error emits a compact conversation warning and applies the summary without a note. A successful note keeps the source messages in `CompactionOutcome.pendingArchive`.

`compactConversationForBudgetWithSteering` adopts `outcome.State` before calling `commitHistoryArchive`. Appends happen in source order only after adoption. An append error emits the same `archive compacted history: ...` warning and stops further appends; the adopted state and its archive note remain in the conversation.

`session.HistoryArchive` (`internal/session/history_archive.go`) implements the interface for the session returned by its `sessionID` callback. `renderHistory` (`internal/session/history_render.go`) writes Markdown oldest first. It preserves user and assistant text, tool-call summaries and status marks, image placeholders, and active skill markers. It omits tool result bodies, reasoning, and sub-agent result bodies. Summary rendering removes history note lines, and skill envelopes are stripped from retained messages by `stripRetainedSkillBlocks` before active skills are re-injected into the new conversation generation.

The session store creates `history.md` in the per-session directory under `~/.config/steiner/sessions/<sessionID>/` when the first non-empty archive append succeeds. `HistoryPath`, `AppendHistory`, and `ReadHistory` are in `internal/session/store.go`. `finishRemovalLocked` removes that directory, recall files included, during session deletion and eviction. Existing compactions are not backfilled.

Forks copy these sidecars. `Store.ForkSidecars` (`internal/session/fork_sidecar.go`) runs after `session.Fork` and before the fork's `Save`, because saving the fork can evict the parent. It copies `history.md` and every regular `recall/*.txt` file atomically with the store's 0700 directory and 0600 file modes, and rejects symlinked directories and files; absent parent files copy nothing. Only a complete copy rewrites the fork's inherited references in its latest generation (`internal/session/fork_rewrite.go`): the parent history path and recall directory named in `HistoryNoteMarker` lines of summary messages, and the read path of a recall marker of the form `[Tool output omitted from active context: recall <name>, read <path>; for long lines use bash head -c/tail -c]` when that path is the parent's recall file for a copied name. The recall directory is rewritten only when at least one recall file was copied, and markers are rewritten only for copied names, so no reference points at a path the fork does not hold. A marker is rewritten only when it is the whole content of a tool message or the whole inner of a sub-agent result envelope, the two shapes compaction writes; marker-shaped user text is left alone, and an envelope is rebuilt through `agent.ReplaceSubAgentResultInner` so its `bytes` attribute stays correct. The marker parser requires the recall name to be one path element with no nested marker prefix, so a bare marker prefix inside a message cannot pair with a later marker's delimiters and hide it. On a copy failure the fork is returned unchanged and the interactive fork paths emit a session-health warning, so inherited references keep pointing at the parent while it exists. Neither fork path pins the parent against eviction: `/fork` refreshes the parent's index entry before saving the fork because `saveSession` rewrites it, while forking a saved session can evict that session when the store already holds `maxSessions` entries, which leaves the failed fork's references dangling.

`wireInteractiveRunner` (`cmd/steiner/interactive_session.go`) supplies an archive keyed by the current interactive session. `phaseHistoryArchive` and `phaseRunner.RunPhase` (`cmd/steiner/cmd_oneshot.go`) key oneshot archives by the phase session. The exec runner leaves `historyArchive` nil, and delegated child runners do not receive one, so archiving is limited to interactive and oneshot phase runs.

### Sub-agents and skills

- `appendPendingSubAgentsLine` (`internal/agent/compaction.go`) appends one `sub_agent_result` user message listing pending sub-agents at the tail.
- Compaction strips skill envelopes from retained messages (`stripRetainedSkillBlocks`), then re-injects the active envelopes as one user message ahead of the retained turns (`replayedSkillMessage`, `internal/agent/compaction_skills.go`). `activeSkillBlocks` scans the whole generation, so an activation in the summarized part still counts. A disabled skill drops out at the next compaction.

### Stateful transcript providers

For `claude_subscription`, the CLI owns the transcript.

- `ParentUsage` (`internal/agent/parent_usage.go`) holds the last parent response's usage in memory. Interactive runs carry it into the next run (`internal/interactive/driver_run.go`). It is dropped when the model or context window differs, and it is never saved.
- After a stateful compaction, the first parent response arms `StatefulFloor` from its `PromptTokens` when that value reaches the selected soft threshold but not the cap. The selected threshold (`statefulUsageReachesSelectedThreshold`) is `compaction_threshold_tokens` when set, otherwise the percent threshold. The soft trigger then waits until usage reaches `min(floor + 10% of window, 90% of window)`.
- At or above 90% (`compactionCapUsagePercent`), the run is marked cap-reached. Its next compaction decision stops the run with `request exceeds context window` without calling the compactor, and emits a critical `likely_lossy` session health event (`statefulCapStop`).
- Summary requests for `claude_subscription` use `claudeSubSummaryTurn`; routing is in [Claude subscription](claude-subscription.md#compaction).

### Escalation and replacement

- `turnProgressor.compactionCount` (`internal/agent/turn_progression.go`) counts applied compaction stages in one run. Each applied outcome adds `outcome.StageCount` (1 or 2) in `compactConversationForBudgetWithSteering`, so one two-stage compaction adds 2. It starts at zero in `newTurnProgressor`. Manual `/compact` starts from zero too.
- `compactionEscalationForFit` (`internal/agent/compaction_escalation.go`) maps the stage count and post-compaction fit to a health event. Below `compactionWarningThreshold` (2): `info`/`stable`, or `warning`/`fragile` when fragile. At 2: `warning`/`fragile`, or `critical`/`likely_lossy` when fragile. From `compactionCriticalThreshold` (3): `critical`/`likely_lossy`. A budget is fragile when the estimated prompt exceeds the hard limit by at least 20% (`compactionBudgetIsFragile`).
- `replacementGuardLocked` (`internal/interactive/driver_host.go`) refuses conversation replacement while driver admissions exist, the driver is busy, or sub-agents are still running (`pendingRefusalLocked`). A refused replacement returns before any swap.

## Durable context state

`ContextState` (`internal/agent/context_state.go`) has two fields:

| Field | Contents |
|-------|----------|
| `RecentToolCalls` | Up to three `summarizeRecentToolCalls` entries from the latest lineage generation, oldest first. Each is a tool name plus summarized arguments. Rebuilt every turn by `enrichContextState`. |
| `TurnCount` | Turn count of the run. |

- `Clone` deep-copies `RecentToolCalls`.
- Argument summaries cut values at 40 characters, and bash commands at 80. `cwd`, `path`, and bash commands are redacted against the absolute cwd root.
- The summary is not in `ContextState`. It lives in the active generation's `SummaryPrefix`.
- File tracking lives on `baseContextManager.fileTracker`, not in `ContextState`. `PostIngestion` rebuilds it from `read` results with a positive turn and never changes messages.
- `dedupReadResult` (`internal/agent/read_dedup.go`) replaces a fresh `read` result with a short note pointing at the turn of that read. The match requires the same path, line range, total lines, and `file_hash` as the most recent matching read. Line-capped reads and reads without `file_hash` are not deduplicated.
- `observeToolResult` (`internal/agent/context_manager_tool_result.go`) returns output from other tools as given.

## Invariants

- Lineage keeps every generation. The latest one is active.
- The cached prefix is byte-stable within a session: the memoized preamble, the static cache partitions, and the sorted tool definitions. Skill toggles change only the next user message.
- Child runs use `agent.Runner` and the same compaction path.
- Summaries are capped. Compaction is lossy, but its output size is bounded.
