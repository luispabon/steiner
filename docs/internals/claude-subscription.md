# Claude subscription internals

User guide: [Claude subscription](../user/claude-subscription.md).

The `claude_subscription` provider drives the signed-in `claude` CLI as a stateful adapter. The CLI is not a stable protocol contract, so this page describes the implementation the tests cover.

## Process pool and session identity

`ClaudeSubscriptionPool` owns CLI processes. Parent normal calls are pooled by `TransportSession`, falling back to the parent transport session and then `default`. Model and effort are not part of the key. Calls for one key are serialized, and a process is reused until teardown. A process that exits is evicted, and its successor reseeds.

Only parent normal calls persist (`claudeSubPersists`). Advisor calls key the pool by their advisor transport session plus `|advisor` (`claudeSubAdvisorSessionKey`): `<session>-advisor|advisor` for the parent and `<session>-subagent-advisor|advisor` for sub-agents. Advisor, sub-agent, and summary calls store no backend state. A parent turn returns an opaque backend state holding the CLI session ID, transport session, sync record counts and digests, final message UUID, and a prompt/tools fingerprint. It holds no message text.

A model or effort change reuses the live process: `set_model` for the model and `apply_flag_settings` for `effortLevel`.

The pool runs `claude --version` and `claude auth status`. The status must report `authMethod` `claude.ai` and `apiProvider` `firstParty`. `loggedIn` is decoded as an explicit boolean pointer. Any explicit `loggedIn:false` is classified as signed out when auth status exits successfully or with exit code 1, and bounded stdout is retained long enough to make that classification. Missing or malformed booleans, timeouts, and unrelated errors remain unknown. The provider never reads a credential file.

The locator is a tracked single-flight job. A signed-out result marks the completed job eligible for one synchronized replacement on a later explicit acquire. No waiter mutates or closes an active job. The advisor usage-recovery path uses a pool-owned, tracked single-flight fresh auth check with an 8 second operation timeout (`claudeSubFreshAuthTimeout`). Callers may stop waiting, but the check remains bounded, and pool shutdown cancels and joins it. When it confirms external logout, the leased session is retired and the request returns an actionable error; no request is replayed. Advisor sessions idle for 60 minutes are reaped (`claudeSubDefaultIdleTTL`). Other sessions stay open until the pool closes them. Session close is bounded by 10 seconds (`claudeSubSessionCloseTimeout`), and pool shutdown by 15 seconds.

`STEINER_CLAUDESUB_RECORD` names a directory for raw stdout capture. The directory is created with mode `0700`, and each per-session JSONL file is written with mode `0600` under an encoded name, so session keys cannot escape the directory. Recordings contain prompts, tool data, file contents, and account details. Before committing a fixture to `internal/provider/testdata/claudesub/`, keep only the representative lines and redact emails, organization IDs, paths, and file contents.

## CLI invocation

Normal sessions use this process shape:

```text
claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --model <model> --tools "" --strict-mcp-config --setting-sources= --disable-slash-commands --settings {"autoCompactEnabled":false,"fastMode":false} --permission-mode dontAsk
```

Additional flags:

- `--system-prompt-file` carries the private system prompt.
- With tools, a private MCP config and an allowlist for `mcp__steiner__*` are added.
- Calls that do not persist add `--no-session-persistence`.
- Restoring stored state adds `--resume <session-id>` and, when a target UUID is set, `--resume-session-at <uuid>`. Forks add `--fork-session`.
- Summary helpers set `--max-turns 1`.
- Effort `none` maps to `--thinking disabled`. A recognized effort (`low`, `medium`, `high`, `xhigh`, `max`) enables adaptive thinking and passes `--effort`. Empty or unknown effort is adaptive without `--effort` (`claudeSubEffort`).

The child environment strips `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, and `CLAUDE_CODE_ENTRYPOINT`. These values override inherited ones: `CLAUDE_CODE_DISABLE_FAST_MODE=1`, `CLAUDE_CODE_RETRY_WATCHDOG=0`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`, `CLAUDE_CODE_SILENT_TURN_REMINDER=0`, `CLAUDE_CODE_TOTAL_TOKENS_REMINDER=off`, `CLAUDE_CODE_TODO_REMINDER_MODE=off`, and `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1`. `MAX_MCP_OUTPUT_TOKENS` is set to a bounded value. Forcing `CLAUDE_CODE_RETRY_WATCHDOG=0` turns off the CLI's unattended retry mode: the CLI does not wait out a capacity error or a usage-limit reset window, and follows its normal bounded retry count before reporting the limit. Steiner then ends the turn on the resulting `*UsageLimitError`.

The CLI still injects account and environment context that these switches do not remove. See [Privacy](../user/claude-subscription.md#privacy).

## Loopback MCP host

Each tool-enabled session starts an MCP host on `127.0.0.1` with an OS-chosen port and a bearer token. Requests without the token are rejected. Tools are published as `mcp__steiner__<name>`, and names over the 64-character limit (`claudeSubToolNameMax`) are shortened with a hash suffix.

The stream registers each tool use ID. The `tools/call` whose `_meta["claudecode/toolUseId"]` matches receives the result. While the tool runs, the handler sends progress notifications every 20 seconds (`claudeSubHeartbeat`).

## Control messages and stream decoding

Conversation uses four control requests: `set_model` when the requested model differs from the live model, `apply_flag_settings` to change effort, `get_usage` before a new user message for the usage gate, and `interrupt` when pending tool work is stale or a call is cancelled. `initialize` is used only by model discovery.

The decoder waits for the assistant-message boundary before treating a tool call as complete, which prevents duplicate text. A tool input that does not parse is recorded on that call as `argument_decode_error`, and the turn continues. The CLI's `__unparsedToolInput` sentinel (`UnparsedToolInputKey`) carries the raw text of an input the CLI could not parse. The decoder checks it against the streamed input.

Every `system` envelope is ignored except `api_retry`, which the CLI emits when it retries a retryable API failure itself. `(*claudeSubDecoder).decodeSystem` accepts it only in `claudeSubPhaseStreaming`, so a notice after message_stop or the terminal result is dropped. The item carries the attempt, the permitted retry count, the delay clamped to a non-negative `time.Duration`, the HTTP status when there was a response, and the failure category; a malformed notice is dropped with a debug record instead of failing the turn. `claudeSubConsume` emits it as a warning `ChatChunk` with `RetryAttempt`, `RetryMaxAttempts` and `RetryDelay` set, `RetryReset` false, and the unexported `cliRetryNotice` marker set, because the CLI retries before it produces output and discards nothing. `claudeSubAPIRetryNotice` reads that marker: the chunk does not close the pre-output retry window and does not trigger a pending replacement warning. `claudeSubNormalTurn` also records that the CLI retried in this attempt and then declines the Steiner pre-output retry, since a fresh process would only repeat the wait the CLI already completed. The agent maps a chunk with `RetryAttempt` set and no reset to `output.DiagnosticKindRetry`, and the advisor emits that kind for both this chunk and the `RetryReset` chunks that carry a diagnostic. `claudeSubEventIsOverage` resolves the `api_retry` subtype before its notification probe and returns false for it, so a malformed notice cannot fail the pool closed; usage-limit detection reads only `rate_limit_event`.

## Transcript synchronization

The sync record is append-only. User and tool messages are compared by content digest (`claudeSubDigest`). Images are excluded from the digest because steiner strips image data after use, and image fingerprints are compared separately. Assistant entries are matched by tool-call IDs, since the CLI may normalize their text. Any other rewrite, omission, or reorder makes the live process unusable for that request: the process is retired, and the request forks or reseeds.

## Session recovery

A new parent process restores stored state only when the stored CLI session ID, prompt/tools fingerprint, and final message UUID match the request history (`claudeSubRestoreFor`). A restore resumes at the stored UUID with `--resume-session-at` when one is set. State owned by another transport session forks instead: `claudeSubRestoreFor` returns Fork when `stored.TransportSession` differs from the key, and the CLI gets `--fork-session`. Any failed check reseeds. A live process that accepts the history is reused as is, even if the prompt or tool set has changed. When a live process rejects the request, the retry reseeds unless the stored state belongs to another transport session (`claudeSubAttachSession`).

A reseed sends the whole non-system history as one user transcript message. Images still in memory are included, and stripped image data does not return. Tool calls in the history are rendered as text.

An assistant message that carries `IncompleteText` is the partial steiner recorded locally when a turn ended early. A partial always has text, because `commitInterruptedAssistant` rejects a blank response, so a non-empty `IncompleteText` is the whole marker. `claudeSubTranscript` renders it under `claudeSubPartialLabel`, which says the text is an interrupted assistant partial, untrusted and locally observed, and ended before the response was complete. The exact streamed text follows inside a fence the text cannot contain: `claudeSubPartialFence` derives the tag from the partial's SHA-256 and returns a fence absent from the text: it rehashes at most `claudeSubPartialFenceRounds` times and then appends an incremented counter until the fence is absent, which terminates because the text is finite. The fence is therefore deterministic, and a `>>>`, a `[user]` or a forged tag inside the text stays text. The interrupted note that the agent appends to the provider projection's `Content` is not rendered, because `IncompleteText` holds the raw text. A complete assistant message renders under the `[assistant]` label with its content and tool calls. `IncompleteText` is `json:"-"` local provenance: no provider sends it, `claudeSubDigest` hashes role, content, and name only, and no persisted state carries it.

A stdin line refused by the CLI's limit fails the turn with `send flattened reseed transcript` wrapped around the limit error (`claudeSubLineTooLargeError`), so an oversized reseed is identifiable. `errors.As` still reaches the typed limit error.

An interrupted run commits its streamed text locally as an incomplete assistant message. That message is not part of the sync record steiner keeps for the CLI transcript, so a restore cannot append it: `claudeSubRestoreFor` refuses the resume, reports the plan reseed branch, and the next turn reseeds from the local history. No request error is raised.

A generation whose backend state was cleared has nothing to restore, so its next request starts fresh and reseeds from the preserved conversation. Backend state is saved with the session, so a crash between retiring a process and saving the session can leave the previously persisted state on disk. That saved checkpoint may be older than the retired transcript, and resuming from it after such a crash is unverified.

## Cancellation safety

A cancelled turn cannot prove event ownership. When a delivery reached the CLI and the caller cancelled it before the turn's terminal chunk, the CLI keeps producing that turn's events and nothing attributes them to a later call. `claudeSubSession.abandon` marks the process unsafe and records a replacement notice for its key in the pool. Two other mid-turn stops abandon the process the same way, because the CLI may keep going after each: a cancelled stale-pending interrupt in `claudeSubFinishPending`, where the interrupt request is queued before its response is awaited, and a `rate_limit_event` that ends the turn inside `claudeSubConsume`.

Every path that could reuse an unsafe process retires it first: `claudeSubAttachSession` for parent and sub-agent calls, `claudeSubAdvisorTurn` for advisor calls, and the summary entry points `claudeSubTryParentFork`, `claudeSubParentInPlace`, and `claudeSubSubAgentSummary`. As a backstop, `claudeSubDeliver` refuses an unsafe process with `errClaudeSubSessionUnsafe` and retires it, so a caller that misses the check still cannot write to it or read its queue.

The replacement notice lives on the pool, not on the session, so eviction, idle reaping, or a failed replacement startup cannot lose it. It is in-memory state: it vanishes with the pool, so a steiner restart before the next request for that key reports no warning. `claudeSubReplacementReport` emits the notice before the recovering attempt's first streamed chunk and does not clear it; the call clears it only through `confirm` after it succeeded. The warning therefore claims only what is certain, that a process behind an earlier unfinished turn was discarded, and never claims a resume, a transcript rebuild or a fresh process, because a retried attempt or a reused live process would make such a claim wrong. An attempt that produces no output reports nothing and leaves the notice pending.

Summaries make no replacement claim. A summary is an auxiliary request: replacing the unsafe parent it found, or reseeding its ephemeral helper, recovers nothing of the conversation, so the notice stays pending for the request that continues it. Helper keys (`key + claudeSubSummarySuffix`) never record a notice.

A conversation reseed also reports that prior context was replayed as one flattened user message (`claudeSubFlattenedReseedWarning`). `claudeSubNormalTurn` sets `claudeSubReplacementReport.flattened` from `claudeSubAttachResult.reseed`, so every reseed branch qualifies: no stored state, a failed restore or checkpoint match, a rejected live process, an exited process, and the retry after a failed resumed attempt. The attempt decides its single warning when it emits it: a pending notice alone reports the replacement wording, a reseed alone the flattened wording, and both at once report `claudeSubReplacedAndFlattenedWarning`, one message carrying both facts. The flattened notice is per request: it is not stored on the pool, so the call that delivered the flattened transcript reports it once and a later call cannot repeat it. A failed call that already reported it does not have it repeated by the next request unless that request reseeds again, which reports its own flattened replay. Summary reseeds and advisor snapshot renders report neither, because a summary is auxiliary and an advisor always renders its snapshot as one message, whether or not anything was reseeded.

The warning travels as a `ChatChunk` diagnostic (`Diagnostic` plus `Severity` `warning`). The agent's streaming turn and the advisor's streaming turn emit it as a provider diagnostic event. A non-streaming call folds it into `ChatResponse.Warnings`, which the agent's non-streaming paths and the advisor's non-streaming path emit as the same event. A folded call that fails returns no response, so its buffered warning never reaches the user; because the notice is cleared only on success, it stays pending and the next request reports it. A streaming call that delivered the warning and then failed also keeps the notice pending, so the next request may repeat the warning: a duplicate, never a silent loss.

A cancellation that lands on a terminal chunk does not mark the process: a final assistant message or a tool-call message ends the delivery and its events are consumed, and a later call settles a stale pending tool call through `claudeSubFinishPending`. A cancellation the usage gate absorbs, before anything is written to the CLI, also leaves the process reusable.

The unsafe process is retired when a later call uses its key, not at cancellation time. Until then its abandoned turn keeps running, and its events stay in the session queue that retirement discards. Pool shutdown retires it too.

## Compaction

`statefulUsageReachesSelectedThreshold` in `stateful_compaction_guard.go` compares the last response's `PromptTokens` with `ModelTokenBudget.CompactionThresholdTokens` when it is set. Otherwise `statefulUsageAboveThreshold` compares against `CompactionThreshold`, a fraction that `deriveEffectiveLimits` sets to 0.70. `compactionUsageThreshold` (also 0.70) is the fallback when that is zero. For this provider, `PromptTokens` is the CLI's total input from the terminal assistant message (`claudeSubUsage.toUsageStats` sums input, cache creation, and cache read tokens). The CLI's result usage covers the whole query, including tool round-trips, so it is not used. A request that does not fit also triggers compaction, as it does for every provider.

A stored compaction summary projects to a user-role conversation message with the fixed historical-context wrapper. `CompactionSourceMessages` counts that message when the generation already has a summary, so a follow-up summary's source prefix includes it and the sync record matches the request.

Summary routing is owned by `claudeSubSummaryTurn` (`claudesub_turn_summary.go`), tried in this order:

- Sub-agent (`ParentTransportSession` set): the summary is marked in place on the sub-agent's own process, which is then retired.
- Parent, tried first (`claudeSubTryParentFork`): when the stored state matches the live checkpoint and fingerprint, an ephemeral helper forks the stored CLI session at the source tail UUID (`--fork-session`, `--max-turns 1`) under `key + claudeSubSummarySuffix`. The live parent is untouched.
- Parent, when forking is not possible or fails before output with an error other than a usage limit (`claudeSubParentInPlace`): the summary is appended in place to the live transcript, and the process is retired.
- Parent with no live process, or whose record cannot take the summary: the request is reseeded on an ephemeral helper with no persistence.

If a compaction candidate omits the leading summary (a summary-prefix-stripped view) while the live CLI transcript holds the projected summary as its first user message, the source prefix does not match. Both parent summary paths decline rather than rewrite the transcript: `claudeSubForkSourceOf` cannot produce a source tail uuid, and `planSummary` returns `errClaudeSubSummaryNoPlace`. The request cold-reseeds on an ephemeral helper (`claudeSubReseedSummary`), whose `claudeSubReseedDelta` sends the whole non-system request history as one user transcript and which is retired afterwards. No live-process history is rewritten.

When a live parent exists, an in-place parent summary retires it whatever the summary's outcome. `claudeSubDeliverTainted` taints the record before the first write, and `claudeSubParentInPlace` retires and releases the process afterwards, so it is never reused. The terminal chunk of a successful in-place summary carries `ClearBackendState` (`claudeSubClearOnDone`). A failed or cancelled in-place summary may or may not deliver a terminal chunk, so `claudeSubParentInPlace` also marks its error with `markBackendStateRetired` and sets the request signal created by `provider.WithBackendStateRetirement`; `provider.BackendStateRetired` and `provider.BackendStateRetirementSignaled` report the retirement. An acquire failure, and a failed cold reseed with no live parent, retire nothing, so their errors stay unmarked; a successful cold reseed still carries `ClearBackendState` on its terminal chunk. A fork helper runs under `key + claudeSubSummarySuffix` and leaves the parent process and its state untouched, so it clears nothing.

## Usage gate

Before a new user message is written, `get_usage` is polled. The refusal rules are in the [extra usage safety gate](../user/claude-subscription.md#extra-usage-safety-gate). Unconfirmed states, including missing fields, are retried with 500ms, 1s, then 2s backoff for up to 15 seconds (`claudeSubUsageGateBudget`). Each `get_usage` is bounded by the 30 second control timeout.

If the live process still cannot confirm, `confirmUsageFresh` asks a new CLI process once, because the CLI caches an incomplete usage read in the running process. Confirmation is serialized pool-wide and bounded to 8 seconds (`claudeSubUsageProbeTimeout`). For advisor calls, only a second fresh usage result that is still definitively not-ready permits the pool-owned `confirmAuthFresh` job to inspect auth status. Credits enabled, cancellation, shutdown, and any successful or unknown usage result retain precedence, so auth cannot authorize a turn or weaken the fail-closed gate. Cancellation, a deadline, or shutdown that arrives during fresh auth overrides the earlier usage refusal.

A `rate_limit_event` whose `rate_limit_info.status` is `rejected` for a plain, non-overage limit becomes a `*UsageLimitError` (`claudeSubRateLimitVerdict`). It ends the turn. Within this provider, `claudeSubShouldRetryTurn` does not retry it on a fresh process, and `claudeSubSummaryTurn` returns it instead of replaying a failed summary fork on the live parent. The shared provider and agent retry paths stop on `AsUsageLimit` (`classifyProviderError`, `RetryableProviderError`, and the agent runner's usage-limit stop reason).

## Provider diagnostics

When a stream-error logger is configured, each model call writes one provider-stream record (`claudeSubStream`) with transport `cli` and `attempts` 1. `call_kind` is `advisor`, `summary`, `sub_agent`, or `normal` (`claudeSubCallKind`), in that precedence. The record carries outcome, duration, chunk count, time to first token, and a bounded error. CLI result text, the stderr tail, and control-response text are not recorded. `partial_stream` is set when chunks reached the caller before the failure. Records have no request URL, headers, or bodies, because the CLI has no HTTP exchange. A CLI decode failure (`errClaudeSubDecodeStream`) is classified `decode_error`.

## Live interrupt probe

`TestClaudeSubProbe` (`claudesub_probe_test.go`) is an opt-in harness that measures the CLI's interrupt and resume behaviour against a real signed-in CLI. It records, per experiment, the ordering of an `interrupt` control response and the turn's terminal result, the result's subtype, `terminal_reason`, `is_error` and `stop_reason`, events that arrive after the result, what happens to a `tools/call` that is in flight when the interrupt lands, whether an interrupt that races a finished turn yields a stray result, whether `--resume-session-at` truncates the on-disk transcript or only hides later entries, and each turn's cache counters. E7 additionally measures the join a crashed turn needs: it SIGKILLs a persisted CLI child it spawned while that child streams a list, then resumes a fork at the earlier assistant uuid and sends one user line carrying the original prompt plus the quoted partial and a continuation note.

The `claudesub_probe` build tag keeps the file out of the package, so `go test ./...`, vet and lint without the tag never compile it. `STEINER_CLAUDESUB_PROBE` selects the mode, and an unset value skips the test.

```bash
STEINER_CLAUDESUB_PROBE=plan go test -tags claudesub_probe -count=1 -timeout 30m -run TestClaudeSubProbe -v ./internal/provider
STEINER_CLAUDESUB_PROBE=run STEINER_CLAUDESUB_PROBE_ACK=i-accept-live-requests \
  go test -tags claudesub_probe -count=1 -timeout 30m -run TestClaudeSubProbe -v ./internal/provider
STEINER_CLAUDESUB_PROBE=run STEINER_CLAUDESUB_PROBE_ACK=i-accept-live-requests STEINER_CLAUDESUB_PROBE_ONLY=E7 go test -tags claudesub_probe -count=1 -timeout 30m -run TestClaudeSubProbe -v ./internal/provider
```

The `-timeout 30m` suits the probe's own 25 minute ceiling: the probe stops with its own message first, and a shorter `-timeout` would cut the run before its report is written.

`plan` resolves the CLI on `PATH` without executing it and prints the argv `claudeSubArgs` builds for each experiment with the load-deciding switches (`--setting-sources`, `--strict-mcp-config`, `--tools`, `--allowedTools`) marked present or absent, the child environment keys from `claudeSubSessionEnv` with values redacted except `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`, `CLAUDE_CODE_RESUME_SHOWS_CUT_OFF_CALLS`, `CLAUDE_CODE_RESUME_PROMPT`, `CLAUDE_CONFIG_DIR` and `HOME`, the working directory, report and raw-capture paths it would create, the expected CLI session-store directory, the model, the experiment selection with the selected experiments' bounds, and the experiment list. It starts no process and creates nothing. `run` additionally requires the acknowledgement variable above, because it spends real subscription requests and writes CLI session files under the CLI configuration directory.

`STEINER_CLAUDESUB_PROBE_MODEL` sets the model (default `haiku`), `STEINER_CLAUDESUB_PROBE_OUT` sets the report path (default `report.json` in a private temporary root with mode `0700` and mode `0600` on the file), and `STEINER_CLAUDESUB_PROBE_CLEANUP=1` removes the transcript files of the session ids the probe itself recorded. Cleanup accepts only ids matching `[A-Za-z0-9-]+` and only removes a file whose directory is exactly the probe's own project directory; every other recorded id is skipped and reported. `STEINER_CLAUDESUB_PROBE_ONLY` is a comma-separated list of experiment ID prefixes (`E7`, `E1,E7`) and runs only the matching experiments, in table order; an unknown prefix or an empty entry fails before anything is spawned. `STEINER_CLAUDESUB_PROBE_E7_TRIALS` sets E7's trial count (1 to 5) and fails when the selected experiments cannot fit that count inside the ceiling.

Processes start through the production pool (`acquire` and `startClaudeSubSession`), so argv, child environment and the loopback MCP host match a normal session. Before init, the spawn seam asserts the argv carries `--strict-mcp-config`, an empty `--setting-sources`, a single `--tools` with an empty value and a single `--allowedTools` for the steiner prefix. Each experiment uses a fresh process and an empty private working directory, publishes one synthetic MCP tool (`probe_wait`), and sends only prompts carrying `PROBE-` markers. A wrapper on the pool's spawn seam records every line in both directions, including control responses the router consumes before they reach the event queue.

The first prompt is gated on the init event. The production session path sends no `initialize` request, and the CLI may report `system`/`init` only after the first user input, so the probe waits 10 seconds for init before writing anything. If init arrives, it is validated directly (`init before input`). If it does not, the probe sends one gating turn and holds every other prompt until init validates. For the non-persisted specs the gating turn is a fixed warmup prompt (`PROBE-WARMUP: reply with the single word ok and do not call any tool`), so no experiment turn is spent on it; for the persisted and resumed processes it is the experiment's own first tool-free prompt (T1 for the parent, T4 for E5's resume and fork processes, the two-block continuation line for E7's resumed fork), so no extra turn enters a stored transcript. While the gating turn runs, and until its own result arrives, any MCP tool call is resolved with an error result and the rejected call ids are reported. Init must arrive and validate within 20 seconds of the gating turn, otherwise the experiment fails. Validation requires the tool list to be exactly `mcp__steiner__probe_wait`, the model to be the requested one or its resolved id, and no MCP server other than `steiner`; `sendPrompt` refuses to write until a process's init has passed. The report states which path happened and records the init event's tools, model, capabilities, CLI version, permission mode and the names in its `plugins`, `mcp_servers`, `slash_commands`, `agents`, `skills` and any hook field, because those are the evidence of what a user configuration loads into a steiner process. A warmup turn is recorded as its own turn, so cache comparisons start at the turn after it.

Each experiment is bounded by its own worst case: 180, 190, 170, 150, 340, 190 and 189 seconds, each above the sum of that experiment's step budgets (including the init gate, the 30 second interrupt control timeout, the tails and a teardown term per started process of two `claudeSubCloseGrace` waits plus a margin). The experiment body spends the same declared step list the bound is checked against, so the two cannot drift, and a self-check pins both relations. The probe's own ceiling is 25 minutes, below the required `-timeout 30m`, so it stops with its own message first. Every experiment fails soft with its error recorded. Each process is always torn down through `retireAndRelease`, and the report records the exit status (or that it is unknown because a bounded teardown left the child unreaped), the child's wait error, the teardown result, the connection error and the number of recorded events the probe never read. An experiment fails when its timeline hit the entry cap, when the process exited before teardown began, or when teardown reported an error other than a bounded teardown that ran out of deadline; a non-zero exit after the probe's own stdin close is recorded evidence, not a failure.

E7 runs one trial in a full run: each trial starts two persisted processes, so it spends both processes' init gates, four waits and two per-process teardown budgets, and E1 to E6 with their teardowns already claim most of the 25 minute ceiling. When E7 is the only selected experiment it derives three trials from the freed budget, and `STEINER_CLAUDESUB_PROBE_E7_TRIALS` overrides the count; the experiment's bound is its own per-trial plan times the resolved count, and a selection that cannot fit the requested count inside the ceiling fails before anything is spawned, as does selecting E7 on a platform without the kill seam. It kills only the CLI child it spawned: `claudeSubProbeKillProcess` reaches the process handle through the connection the spawn seam returned and sends SIGKILL to that process alone, so no other process is ever signalled, and the coordinator's own tree termination still runs at teardown. A trial fails when the killed turn already carried its result at the kill point (`finished before kill`), when the exit is anything but status `-1` with a `signal: killed` wait error (`exited before kill`), or when the resumed turn ends with an error result. The killed process is marked `ExpectedCrash`, which exempts only that SIGKILL exit and a teardown result carrying `signal: killed` or the bounded-teardown allowlist; any other teardown error still fails. The quoted partial is read only after the process exited and its events were drained, and the resumed process's init gate gets the experiment's declared continuation budget for that turn's result. Each trial reports the tail of the partial, the head of the continuation, the item numbers either side of the seam with duplicates, gaps and whether the continuation finished a cut item number, whether the model mentioned the interruption, the continuation's four cache counters, the fork's session id, and a verdict in this precedence: `empty` (no text or an error result), `no-items`, `restart`, `duplicate`, `gap`, `short` (the list stops before item 200), `commentary`, and `clean`, with aggregate counts across the trials. Cleanup records both the original and the forked session ids.

The report is JSON: CLI version, redacted environment shape, argv and load-deciding switches per process, per-experiment timelines, MCP call samples with each call's outcome (waiting, result stored, claimed by a late result, cancelled or closed by host teardown), transcript snapshots (line counts and entry types and uuids, never content) and derived findings. The report and the raw stdout capture always live inside the probe's private temporary root, which is kept after the run; an inherited `STEINER_CLAUDESUB_RECORD` is overridden, so capture never lands elsewhere. Results are evidence for the CLI version and account they ran on, not a protocol guarantee.

## Model discovery

Discovery runs a short-lived CLI under a 20 second outer budget (`claudeSubDiscoveryTimeout`): 12 seconds for work and 8 seconds reserved for cleanup. It reads the `initialize` response, skips the `default` alias, and keeps the first entry for each resolved model ID. Failure or an empty usable result returns the static fallback catalog.
